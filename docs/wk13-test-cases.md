## 3. บั๊กที่พบระหว่าง Integration และวิธีแก้ (Reproduce → Isolate → Fix → Verify)

| # | อาการ | สาเหตุ | การแก้ | ยืนยันด้วย |
|---|---|---|---|---|
| 1 | โค้ดเดิม `orderModel.js` / `menuModel.js` รันไม่ได้ | `require('../config/db')` แต่ไม่มีไฟล์ และไฟล์อยู่ผิดโฟลเดอร์ | ย้ายไป `code/src/models/` และสร้าง `config/db.js` | server start ได้, TC ทั้งหมด |
| 2 | สต็อกติดลบได้ถ้าสั่งเกิน | `createOrder` เดิมลดสต็อกโดยไม่ตรวจ | ตรวจสต็อกหลัง `SELECT ... FOR UPDATE` ใน transaction | TC-15, TC-20 |
| 3 | ผู้ใช้แก้ราคาได้เอง | เดิมรับ `unitPrice` จาก client | ใช้ราคาจาก `menu_item` เท่านั้น | TC-13 |
| 4 | ตาราง `stock_movement` ไม่ถูกใช้ | ยังไม่มีโค้ดเขียนลงตาราง | บันทึกทุกครั้งที่ขาย/เติม/ปรับ | TC-10, TC-31, TC-34 |
| 5 | ตัวเลือกสาขาบนแถบด้านบนอ่านไม่ออก (ตัวหนังสือสีขาวบนพื้นขาว) | `select` สืบทอดสีตัวอักษรจาก topbar | กำหนดสีให้ `select` ใน CSS | ตรวจภาพหน้าจอซ้ำ |
| 6 | TC-42 ไม่ผ่านรอบแรก (ได้ 680 คาดว่า 640) | **ค่าคาดหวังในชุดทดสอบคำนวณผิดเอง** ระบบคำนวณถูก (140 + 45 + 135 + 360 = 680) | แก้ค่าคาดหวังในเทสต์ | TC-42 |
| 7 | ลำดับ Top 5 ไม่ตรงกับที่คาด เมื่อ Latte กับ Cappuccino ขายได้เท่ากัน | กติกาเรียงเมื่อยอดเท่ากันยังไม่ได้เขียนไว้ใน requirement | กำหนดให้เรียงตามจำนวน → ยอดเงิน → ชื่อเมนู และเขียนไว้ใน SRS ข้อ 3.4 | TC-42 |

**จุดที่ป้องกันไว้ตั้งแต่ตอนเขียนโค้ด (ไม่ได้เกิดเป็นบั๊ก แต่ควรรู้):**
- mysql2 คืนค่า DECIMAL เป็น string โดยค่าเริ่มต้น (`"45.00" + "50.00"` จะกลายเป็นข้อความต่อกัน) จึงตั้ง `decimalNumbers: true` และคิดเงินเป็นหน่วยสตางค์ใน `Order.js`
- เวลาในฐานข้อมูลอาจไม่ใช่เวลาไทยถ้าเครื่องตั้ง timezone อื่น จึงตั้ง `timezone: '+07:00'` และ `SET time_zone` ทุก connection
